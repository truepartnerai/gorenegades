# Publishing SOP

## The Simple Version
Darin creates or supplies the raw material. ChatGPT turns it into finished media and publishes it.

### Darin's job
Provide any one of:
- a voice dump
- a video file
- a video link with accessible source media
- podcast audio
- transcript
- Power Hour recording/transcript
- email
- social post
- rough notes
- customer question
- old content worth reviving
- a simple idea

Then give the desired instruction:
- "Draft this."
- "Make this an article."
- "Make this a podcast."
- "Turn this into everything."
- "Publish this."

### ChatGPT's job
1. Identify the strongest core idea.
2. Decide which format(s) fit.
3. Preserve Darin's actual argument and voice.
4. Edit for clarity, usefulness, and structure.
5. Create title, description, category, tags, metadata, CTA, and internal links.
6. Prepare audio/transcript where needed.
7. Publish to the Astro content system when authorized.
8. Verify deployment.
9. Suggest useful derivatives without creating filler.
10. Maintain the content library and feed integrity.

## Article Workflow
Source → extract thesis → outline → draft → voice pass → factual/claim check where needed → metadata → internal links → CTA → publish → verify.

Minimum article package:
- title
- description
- publication date
- category
- tags
- author
- body
- relevant CTA

Use current publication date for newly created articles unless the piece is a genuine historical migration.

## Podcast Workflow
Source audio/video → audio file if needed → episode title → description/show notes → metadata → episode page → RSS item → publish → feed check.

For migrated episodes:
- preserve original GUID
- preserve original publish date
- preserve original enclosure/file metadata where possible

For new episodes:
- use a stable public audio URL
- record exact byte size/media type if RSS requires it
- add episode number only when the numbering system is deliberate

## Video-to-Podcast Workflow
If Darin uploads the actual video file:
1. extract audio
2. normalize/encode to podcast-ready audio as appropriate
3. create transcript if useful
4. create podcast metadata/show notes
5. create episode page and RSS item
6. optionally create article/email/short-form derivatives

Do not pretend a platform page URL is the same as having the source video file.

## Repurposing Workflow
A single source may become:
- article
- podcast
- email
- social posts
- short clips
- playbook
- Power Hour recap
- nurture/follow-up asset

Choose only the derivatives that add value.

## Review Levels
### Fast publish
Use when Darin says "publish," "go," or clearly approves the content direction.

### Draft/review
Use when Darin says "draft," asks for options, or the piece contains substantial new positioning.

### Extra verification
Use when the piece includes:
- statistics
- legal/regulatory claims
- medical/financial claims
- political claims
- rapidly changing technology/product details
- claims attributed to named people/companies

## Publishing Checklist
Before going live:
- title is clear
- opening earns attention without hype
- article/episode has one central idea
- Darin's voice is recognizable
- no unsupported claims
- frontmatter/schema valid
- CTA fits the content
- internal links make sense
- no fake date/history
- podcast GUIDs preserved where required
- deployment verified

## Default Ongoing Rhythm
Unless Darin changes it:
- 1+ useful article per week
- 1+ useful podcast episode per week when source material exists
- repurpose the strongest pieces into email/social
- periodically refresh older high-value material instead of only producing new material
